## Goal

Introduce cheap bounded judgment without mixing it with policy, keeping the AI SDK's experimental
evaluation API isolated inside its own adapter package. Deliverable: a reusable System-One decision
layer.

## Deviations from the plan

- **Confidence is harness-derived, because the AI SDK exposes no portable measure.** The installed
  guide states plainly that the SDK "does not promise calibration across providers" and that a
  provider's own statistic "is not ... a portable confidence measure". `deriveConfidence()` defines
  one rule per question kind in core, once. ADR-0042.
- **Cost is always stored `null`.** `experimental_evaluate`'s result carries token counts only; no
  cost field exists anywhere in the installed API to read. An estimate would be indistinguishable
  from a reported number once persisted, so the column is nullable and the null is a measurement.
  ADR-0042, ADR-0045.
- **The decision engine emits no trace events of its own.** The workflow runtime already owns the
  `decision.started`/`decision.completed`/`decision.failed` span around a `jev` node, and a batch
  call answering several questions corresponds to no single node span. ADR-0042.
- **Banding fails closed twice over**: a `null` confidence and an uncalibrated question (no bands at
  all) both resolve to `human-review`, never to a default `auto`. ADR-0042.
- **`ScoreQuestion` declares an ordered `levels` rubric, not a `min`/`max` pair**, because a bare
  numeric range says nothing a calibration fixture can check. ADR-0042.
- **A policy attaches to a question bundle, not to the decision port.** One port serves every `jev`
  node in a workflow, and different nodes ask different questions; a port-level policy would
  necessarily be wrong for one of them, demonstrated by the vendor fixture's unpolicied `verify`
  node. ADR-0045.
- **The example's `classify` node batches all three build-plan questions in one Jev call**, and its
  `branch` routes on the policy's `route` output rather than on the model's raw `category` judgment
  — separating "what category is this vendor" (Jev's judgment) from "what do we do about it"
  (the organization's decision), which the plan's fused `clear | research | uncertain` category
  would have made decorative.
- **`verify` is a core primitive, not wired into the vendor workflow.** Feeding a field's repair
  instructions back into the same logical agent task needs a node type that re-enters a node with a
  repaired input, which the IR does not express today; the primitive and its acceptance criterion
  are complete without it, and M6 is where a feeding-back node type would be added.
- **Live Jev never ran.** No AI Gateway credential exists on this development host. Every acceptance
  criterion touching a real model is instead demonstrated by the harness path — question, batch,
  policy, band, persistence, route — end to end against a deterministic fixture engine, with the two
  `live:jev`-tagged files skipping with a printed reason.
