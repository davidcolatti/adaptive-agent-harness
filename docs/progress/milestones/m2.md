## Deviations from the plan

- `run.aborted` was added to the closed trace-event taxonomy. The plan lists
  only `run.started`/`completed`/`failed`; a cancellation filed as
  `run.failed` would report every abort as a defect in the ledger and in
  every quality metric built on it. ADR-0031.
- Node 24.21.0's built-in `crypto.randomUUIDv7()` was measured and rejected
  for id generation, in favor of a harness-owned generator with an explicit
  monotonic counter. ADR-0030.
- No `attempts` table exists. An attempt is an ordinal (`runs.attempt`,
  `trace_events.attempt`), not an entity; `AttemptId` (ADR-0030) has no field
  yet. ADR-0036.
- `Job` has no `createdAt` field. Creation time is derived from the UUIDv7
  id's embedded timestamp (`entityIdTimestampMs`/`entityIdTimestamp`), so
  there is exactly one source of truth for it. ADR-0032.
- A run-scoped `TraceRecorder`, not the `TraceWriter`, owns `sequence`. The
  build plan does not say who assigns it; the harness and the eve adapter
  both minting their own counter (M1) would have let them collide. ADR-0031.
- The harness CLI lives in `packages/observability`, not a `packages/cli`
  the build plan's repository layout does not name. `packages/observability`
  is itself the plan's own planned-but-unbuilt package, opened by the first
  thing that needed it. ADR-0037.
- `Job.contracts.sop` stays an unversioned bare identifier rather than
  gaining a version field. The `sop` component of the behavior fingerprint
  captures content changes directly; a hand-maintained version would be a
  second, driftable source of truth. ADR-0034 (closing ADR-0032's open
  question).
- A run's actual output value is not persisted anywhere durable in this
  milestone. `HarnessRunResult.output` stays in-process, trace payloads are
  identity-only by rule (ADR-0031), and the `artifacts` table exists only in
  its minimal keyed shape; a durable output is M5's `artifacts` work.
- `harness.run()` gained a second throwing case beyond input validation: a
  domain's behavior-descriptor loader throwing, or an unreachable/failing
  `Storage`, now throws before `run.started` (nothing spent) rather than
  ever recording an unfingerprinted or falsely-successful run. ADR-0034,
  ADR-0036.
