## Deviations from the plan

- **`WorkflowDefinition` carries `version: string`**, which the plan's M4-T1 example omits.
  North-star invariants 3 and 4, `FallbackContext.workflow.version`, and M4-T7's own
  idempotency-key formula ("run + **workflow version** + node + logical item + attempt") each
  require one. ADR-0038.
- **`domain` stays a plain id**, not the version-pinned `DomainRef` `Job.domain` carries. The
  router (M5) matches a workflow to a job on domain id plus job type; pinning a domain version
  would break that match on every domain version bump, for a reason unrelated to the workflow.
  ADR-0038.
- **Node input flows through a closed five-case `Binding` model** (`input`, `node`, `item`,
  `literal`, `object`), not an expression language. AD-013 limits v1 compilation to structural
  composition; an embedded expression language would be executable content a compiler could
  invent and a fingerprint could not distinguish from data. ADR-0038.
- **A `branch` node is pass-through**: its output is the value it routed, unchanged, with the
  chosen label and target recorded only in its `node.completed` trace payload. ADR-0040.
- **Any cycle is invalid**, not merely a cycle undeclared as a bounded loop. Repetition is
  expressed by `map`/`loop` containment, never by a back edge, so there is no legitimate cycle to
  distinguish from an illegitimate one and no judgment call in the one place that must not have
  one. ADR-0039.
- **Only `agent` and `call` nodes may declare tool grants**, stricter than M4-T8's literal text.
  Every other node type runs a registered handler or policy, asks a question, writes an artifact
  or routes control, and a grant on one would be permission nothing reads. ADR-0039.
- **`node.*` trace payloads carry input and output**, amending ADR-0031's identity-only payload
  rule for `node.started`/`node.completed`/`node.failed` only. "Persist node result" has nowhere
  else to go in a milestone that forbids durability, M6's replay needs the values, and redaction
  (ADR-0035) still sits above the buffer so secrets are stripped regardless. ADR-0040.
- **A node that exhausts its retries escalates rather than fails**; `failed` is reserved for
  defects the validator should have prevented. `asAgentRuntime()` maps an escalation to a
  `FailedAgentExecution` carrying a `WorkflowError` whose `details.fallback` is the envelope as
  JSON — a deliberate stopgap, wrong in the way M5 fixes: an escalation is not the same thing as a
  defect, and M5's router is what gives `escalated` its own status. ADR-0040.
- **Jev questions are answered by a documented fixture `WorkflowDecisionPort`**, not Jev. M3 owns
  the question contract and the `DecisionEngine`; a question is deliberately not a
  `CapabilityKind`, which is what lets M3 and M4 run in parallel. The fixture lives in
  `apps/example-agent`, not `@internal/workflow`, because it is this domain's placeholder, and is
  deleted when M3 lands. ADR-0038, M4-T10.
- **An `artifact` node's output is `{ artifactId, name, contentType? }`, with `artifactId` a plain
  string** from an in-memory `ArtifactStorePort` default; where an artifact is actually stored, and
  what an id means durably, is M5's decision. M4-T3, M4-T6.
- **The local runtime deliberately builds no durability**, per the task's own instruction: a node
  result lives in run state, in the returned `WorkflowRunResult`, and in the trace, and nothing
  else. M4-T6.
- **No `attempts` table or durable workflow-run row was added.** A compiled workflow run is
  exercised entirely through the existing `runs`/`trace_events` tables via `asAgentRuntime()`;
  `workflow_versions` (M2-T5's minimal keyed placeholder) stays empty until M5's registry fills it.
